# Clearance: File & Folder Purpose, Project Flow, Main Algorithms & Tech Stack ✅

## Quick summary
This document explains the purpose of the repository's main files and folders, describes the overall project flow, and lists the core algorithms and technology stack used so contributors can quickly understand, run, and extend the project.

---

## Project flow (high level) 🔁
1. Data generation / physics simulation
   - Run TORAX simulations to produce baseline physics datasets (NetCDF) and parameter sweeps.
   - Key files: `torax/run_simulation_main.py`, `torax/final_working_sweep.py` → outputs written into `data/`.
2. Physics analysis & response extraction
   - Analyze time-series and radial profiles to compute response/sensitivity matrices and diagnostic plots.
   - Key files: `torax/complete_plasma_analysis.py`, `physics_analysis/complete_physics_analysis_report.md` → produce `response_matrices.json` and figures in `outputs/plots/`.
3. Surrogate training & validation
   - Train lightweight surrogate (linear) on simulated data for fast evaluations during RL and experiments.
   - Key files: `linear_surrogate/linear_plasma_surrogate.py`, artifacts: `models/linear_surrogate_model.pkl`, `linear_surrogate/response_matrices.json`.
4. RL environment & experiment design
   - Wrap surrogate/physics into a Gym-compatible environment: `plasma_control_env.py` (action = coil currents, observation = plasma metrics).
5. RL training & evaluation
   - Train agents using PPO; track performance using CSV logs and TensorBoard; save policy artifacts.
   - Key files/folders: `simple_plasma_training.py`, `rl_logs/training_config.json`, `rl_training_logs/`, `rl_models/`.
6. Analysis & visualization
   - Produce evaluation plots and analysis dashboards under `outputs/plots/` and `physics_analysis/`.
7. Deployment & demos
   - Provide demo scripts and usage examples for running trained policies/inference.
   - Key files: `plasma_deployment.py`, `DEMO_FILES_TO_RUN.md`, `EXECUTION_GUIDE.md`.

---

## Main algorithms & techniques ⚙️
- Surrogate modeling: Linear regression (Ridge / L2) trained per-output with `StandardScaler` for feature scaling; used for fast prediction and sensitivity estimation.
- Response / sensitivity analysis: Response matrices mapping actuator changes (coil currents) → observable deltas; used for interpretability and control design.
- Reinforcement learning: Proximal Policy Optimization (PPO) as the primary policy optimization algorithm; episodic training with evaluation and checkpoints.
- Physics models (TORAX): Quasilinear transport and physics source models, transport coefficients, profile updaters used to generate high-fidelity datasets.
- Validation tools: Time-series analysis, frequency-domain checks, coefficient-of-variation and cross-correlation diagnostics.

## Tech stack & libraries 🧰
- Language: **Python 3.8+**
- Numerical & data: `numpy`, `scipy`, `pandas`, `xarray`, `netCDF4`
- ML & surrogate: `scikit-learn` (Ridge, StandardScaler)
- RL: `stable-baselines3` (PPO), `gymnasium` (env API), `torch`/PyTorch runtime
- Visualization: `matplotlib`, `seaborn`, optional `plotly`
- Logging & monitoring: `tensorboard`, CSV logs (pandas)
- Dev & tests: `pytest`, Sphinx for docs in `torax/docs/`

> **Note:** The codebase contains TORAX implementations and tests in `torax/_src/`; these are numerical/physics modules (often compiled or JIT-accelerated) and represent the high-fidelity physics used to train/validate surrogates.

## File & folder map (concise) 📁
- Top-level files
  - `README.md` — Project overview and quickstart.
  - `requirements.txt` — Python dependencies.
  - `EXECUTION_GUIDE.md`, `DEMO_FILES_TO_RUN.md` — How-to run experiments and demos.
  - `clearance.md` — This file.

- `data/` — Input datasets and parameter sweep configurations (`synthetic_complete_physics.nc`, `parameter_configs/`).
- `linear_surrogate/` — Surrogate model code and response matrices (`linear_plasma_surrogate.py`, `.pkl`, `.json`).
- `models/` — Canonical model artifacts and response matrices (production copies).
- `outputs/` — Plots and summaries generated by analysis runs.
- `physics_analysis/` — Analysis scripts and full reports (`complete_physics_analysis_report.md`).
- `rl_logs/` & `rl_models/` — RL experiment configs, logs, tensorboard traces, and saved policy artifacts.
- `torax/` — Core physics module with `_src/` (transport models, sources, tests), examples, and docs.
- `torax/tests/`, `pytest.ini` — Test harness and small input datasets for CI.
- Documentation & governance files (`CLEANUP_SUMMARY.md`, `GO_NOGO_DECISION.md`, `Project_Progress_Report.md`, etc.)

## Quick validation & run examples ✅
- Minimal inference (surrogate):

```bash
pip install -r requirements.txt
python -c "from linear_surrogate.linear_plasma_surrogate import LinearPlasmaSurrogate; s = LinearPlasmaSurrogate(); print(s.predict([0,0,0,0]))"
```

- Short RL smoke run (reduce timesteps or use quick config):

```bash
python simple_plasma_training.py
```

- Run core physics tests:

```bash
pytest torax/tests -q
```
